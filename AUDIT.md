# Memory Subsystem Audit

Running findings log for the memory-architecture work. Design lives in
[`docs/MEMORY_ARCHITECTURE.md`](docs/MEMORY_ARCHITECTURE.md). **Negative results
are recorded here too** — a suspected problem that turns out to be clean is worth
exactly as much as one that is real, and stops the next pass re-chasing it.

Convention: **CONFIRMED** = verified against the code or measured on the device.
**REFUTED** = tested and found not to be true. **OPEN** = suspected, not yet
verified. **SUPERSEDED BY Bnn** = was true when written and a later finding
changed the thing it describes — the entry stays as the record of what was
believed, and the pointer is what stops it being read as a statement about the
engine today. Entries are appended, so the sequential reader gets the correction
for free; the pointer is for the one who lands here from a grep.

| G14 | **`tools/check_alloc_sites.py` is FILE-granular, so step 5 can complete with the gate reporting zero progress.** `read_allowlist()` strips everything after `#`, so the per-file site counts it writes are comments; pass/fail compares sets of *files*. `engine_scheduler.cpp` has 17 sites of which ~6 are per-request — removing all 6 leaves the file listed and the gate silent. | G21 | **Two measurements 20 minutes apart are not an A/B, even with tight trials.** The pre-push gate failed at −5.72 % decode. | G19 | **`cudaMemPoolAttrReservedMemCurrent` drops to 0 on a trim even when nothing was returned — assert on `UsedMemCurrent`.** Replacing `EngineRelaunchTest`'s unsound `cudaMalloc` probe with a pool-level check, I first asserted on *reserved*. | G18 | **A successful `cudaMalloc` proves nothing about free VRAM on WSL2/WDDM.** A 28 GiB allocation succeeds on a 32 GB card with 22.6 GiB reported free — the driver oversubscribes into host memory and returns `cudaSuccess`. `EngineRelaunchTest` uses exactly such a probe to decide "under-reported, not leaked", and I read that as evidence before checking it. **Time the memory instead**: a 3x `cudaMemset` over the allocation runs at ~1530 GB/s when resident and ~237 GB/s when spilled, so one bandwidth measurement settles what an allocation success cannot.
