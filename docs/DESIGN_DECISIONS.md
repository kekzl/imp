# Design decisions

Things imp deliberately does not do. Absences without a reason are gaps and live in
[`LIMITATIONS.md`](LIMITATIONS.md).

| decision | reason / measurement | source |
|---|---|---|
| No multi-GPU, no tensor parallelism; not a roadmap item | consumer Blackwell has no NVLink; tensor parallelism on bandwidth-bound batch=1 decode moves activations across PCIe every layer, net-negative on imp's workload. Reopens if a consumer card ships a high-bandwidth inter-GPU link, or the workload moves to large-batch serving | - |
| No CPU inference path, no AVX kernels | CPU-computing cold MoE experts from host RAM: 62.5 GB/s streaming read, 16 threads, 14.0 ms/token for a 120B-A5B shape (round trips included); streaming the missing expert into VRAM and computing on GPU costs 4.7-8.9 ms/token (median reuse distance 2 tokens, LRU at 40 % residency hits 88.7-96.2 %). Reopens if a model's active expert set defeats the LRU, or host memory bandwidth changes class | [PROV: date=2026-08-10 hw=this host] |
| Blackwell only, and specifically consumer Blackwell | `sm_120a` SASS with a `compute_120f` PTX fallback, nothing else; a second architecture means a portability layer in the hot path or a second kernel set, both cost more than this project has | [`internals/ARCHITECTURE.md#target-architecture`](internals/ARCHITECTURE.md#target-architecture) |
| No FP4 cuBLASLt path; CUTLASS is the primary GEMM path | no FP4 cuBLASLt kernels exist on `sm_120`; FP8 prefill is unavailable for the same reason, not a preference | - |
| CHANGELOG is 1-3 lines per entry, not a journal | the CHANGELOG and release page are the only artefacts read by people who never opened the repo; a long entry buries the line the reader came for; the investigation lives in `docs/` and the PR | - |
| No GPU runner in CI; `test` job stays gated behind `vars.HAS_GPU_RUNNER`, off | a hosted GPU runner costs more than this project spends; a self-hosted one on the maintainer's only card would contend with the measurements it exists to protect; `make verify-fast` before push is the only thing that ever runs a CUDA kernel against a correctness or performance check ([`LIMITATIONS.md`](LIMITATIONS.md)) | - |
| Speculative decoding stays opt-in, none is on by default for every model | economics are per-model, measured both ways: prompt-lookup n-gram is default-on for batch-1 greedy dense (drafts are free); Nemotron-3.5's MTP head accepts 41 % at depth 1 offline and 39 % on the serving path but still costs 51 % of decode (~1.41 tokens emitted per verify chunk); NVIDIA's own DSpark drafter measures -42 % in vLLM on the same card (verify step costs ~4 decode steps, returns 1.7 tokens). Reopens if the draft path becomes capturable, or a model's verify ratio drops far enough | - |
| Speculation stays refused for non-greedy sampling and inside a budgeted think block (#1538, #1539) | Qwen3-14B-Q6_K, alternating arms: `temperature: 0.7` (default) 157.79/158.46 tok/s, 0 verify steps; `temperature: 0` (eligible) 157.61/157.87 tok/s, 6 verify steps, 18.6 % acceptance, 5.83 tokens/verify against 51-68 ms/verify vs a 6.3 ms decode step: a verify costs 8-10 decode steps and returns under 6 tokens. Think-gate A/B, same method: shipped 162.43/162.96 tok/s (12 verify steps) vs relaxed 157.92/157.85 (24 verify steps), -3.0 % for double the verify steps; relaxing the gate alone is also incoherent, the acceptance loop breaks on `in_think_block` too (`engine_spec_ngram.cpp`). Reopens if a model's verify ratio clears its cost; removing the greedy restriction additionally needs accept-with-min(1,p/q) plus resampling instead of argmax comparison | - |
| NVFP4 residual add stays a separate kernel: CUTLASS epilogue keeps beta = 0, `o_proj`/`down_proj` pay a residual copy plus elementwise add (#1547, built and measured, not shipped) | Qwen3-14B-NVFP4, 3 alternating rounds: prefill fusion win buried inside the unchanged arm's own 43.8 % spread (15787/22707/20896 tok/s), issue's own ceiling put the prize at ~1.5 %; decode with speculation off (isolates the kernel) neutral, 159.97 vs 160.00 tok/s; decode with speculation on (default) 272.2 vs 354.4 tok/s (-23 %) is a benchmark artefact, not the fusion: fused epilogue rounds once (FP32 accumulate) where copy-plus-add rounds twice, changing the token stream and n-gram acceptance (99.8 % -> 98.8 %, 8.15 -> 6.75 tokens/verify on a repetitive bench prompt; on a real request the same evening acceptance is 18.6 %, where a point is noise). The wiring is also not the two-step the issue describes: with the epilogue taking beta and a test exercising it, `AlphaIsActuallyApplied` left a sticky `invalid argument` reported by the next GEMM's own guard, three runs of three, against three clean runs of the same pair without it; opening this needs that understood first. Reopens if the prefill win can be measured above the host's spread, or a workload is found where the changed rounding does not move the token stream | [PROV: commit=4cb36025 date=2026-08-24 hw=RTX5090 model=Qwen3-14B-NVFP4 cmd=`imp-cli --bench --bench-pp 512 --bench-reps 3`] |
| PDL device half added 2026-08-31; the 34 `pdl::launch` sites and graph-edge rewrite from the earlier decision stay, the device half is no longer left out (#1655) | before: no kernel called `cudaTriggerProgrammaticLaunchCompletion()` or `cudaGridDependencySynchronize()`, so a converted graph edge released the consumer exactly where the default edge did; Qwen3-8B-Q8_0, `runtime.no_pdl` true/false, 3 alternating rounds: wiring off 12508/12630/12462 tok/s prefill, 385.8/387.8/385.5 tok/s decode; wiring on 12455/12531/12091 prefill, 390.0/381.8/382.3 decode; off is 0.4 % ahead on prefill and 0.9 % on decode, both inside the arms' own spread - cost was zero (`is_enabled()` returns before the per-launch set lookup when `no_pdl` is set, so that lookup is inside the measurement). After adding the device half (`src/core/pdl_device.cuh`: registered decode kernels call `griddepcontrol.wait` before their first global access, `launch_dependents` after their last input read; `cuda_graph.cu` converts an edge only when the consumer is registered): Qwen3.8-27B-NVFP4, M=1 spec-off +1.7 % median, 32-stream aggregate +1.3 % median, 3/3 alternating pairs positive, steady-window GPU idle 13.6 % -> 10.8 %. `runtime.no_pdl=true` disables both halves. Reopens if a further producer/consumer pair is completed and measures more overlap | [PROV: commit=d38ad8a9 date=2026-08-24 hw=RTX5090 model=Qwen3-8B-Q8_0 cmd=`imp-cli --bench --bench-pp 512 --bench-reps 3 --set runtime.no_pdl=<v>`] |
