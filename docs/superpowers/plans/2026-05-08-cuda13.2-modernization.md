# CUDA 13.2 Modernization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt `cudaMemcpyWithAttributesAsync` at two recurring H2D sites (layer offload, vision pipeline) and Blackwell `add.f32x2` via `cub::SimdSum<float2>` at the gemv_dp4a partial-finalize sites. No perf restructuring; semantically null at neutral attributes.

**Architecture:** Two independent commits, each touches one API. No new wrapper layer, no public-API change, no new tests. Changes are bit-exact at neutral attribute values, so existing `make test-gpu` + `make verify-fast` are the regression gate.

**Tech Stack:** CUDA 13.2 (host + container toolkit), CUB ≥ 2.5 (bundled CCCL), nvcc `arch=compute_120a` (RTX 5090 sm_120a only), GTest harness, `IMP_CUDA_CHECK_LOG` macro.

**Spec:** `docs/superpowers/specs/2026-05-08-cuda13.2-modernization-design.md`

### Task 2: Adopt `cudaMemcpyWithAttributesAsync` at recurring H2D sites

**Files:**
- Modify: `src/memory/layer_offload.cu:197-198` (expert weight streaming, recurring)
- Modify: `src/runtime/vision_pipeline.cpp:93` (image upload, recurring)
- Test: existing `make test-gpu` + `make verify-fast` (no edits)

**Why no new test:** at neutral attribute values (`srcAccessOrder = Stream`, `srcLocHint = HostNumaCurrent`), `cudaMemcpyWithAttributesAsync` is documented as semantically equivalent to `cudaMemcpyAsync` for stream-ordered host buffers. Both target sites already pass their host pointers through stream-ordered ownership contracts (offload manager, vision pipeline), so the change is null behavior. Existing layer-offload + vision e2e tests cover the paths.

**Local-style note:** `layer_offload.cu` already wraps `cudaMemcpyAsync` in `IMP_CUDA_CHECK_LOG(...)`. `vision_pipeline.cpp` does NOT (the existing call at line 93 is unwrapped, and so are the surrounding `cudaMalloc`/`cudaStreamSynchronize`/`cudaFree` calls). Match local style at each site — do not introduce error checking at vision_pipeline.cpp as part of this change.

- [ ] **Step 1: Modify `src/memory/layer_offload.cu` — expert streaming H2D**

Find the upload loop at lines 196-199:

```cpp
    for (const auto& e : entries) {
        IMP_CUDA_CHECK_LOG(cudaMemcpyAsync(dst_base + e.offset_in_slot, e.host_ptr, e.raw_bytes,
                                           cudaMemcpyHostToDevice, slot.transfer_stream));
    }
```

Replace with:

```cpp
    cudaMemcpyAttributes attrs{};
    attrs.srcAccessOrder = cudaMemcpySrcAccessOrderStream;
    attrs.srcLocHint     = { cudaMemLocationTypeHostNumaCurrent, 0 };
    attrs.dstLocHint     = { cudaMemLocationTypeDevice, 0 };
    attrs.flags          = 0;
    for (const auto& e : entries) {
        IMP_CUDA_CHECK_LOG(cudaMemcpyWithAttributesAsync(dst_base + e.offset_in_slot, e.host_ptr,
                                                         e.raw_bytes, &attrs, slot.transfer_stream));
    }
```

Note: hoist the attrs struct out of the loop (it's invariant per layer-upload). The struct is small (4 fields) and zero-initialization plus the four field assignments compiles to a few stores; the loop body itself is unchanged in semantics.

chore(memcpy): adopt cudaMemcpyWithAttributesAsync for recurring H2D paths

CUDA 13.2 ships cudaMemcpyWithAttributesAsync with an explicit
cudaMemcpyAttributes struct (srcAccessOrder, srcLocHint, dstLocHint,
flags). Adopt it at the two H2D paths that fire on the inference hot
loop:

- src/memory/layer_offload.cu: expert weight streaming for MoE offload
- src/runtime/vision_pipeline.cpp: per-request image upload

Attribute values are semantically equivalent to plain cudaMemcpyAsync
on stream-ordered host buffers (srcAccessOrder=Stream), with a NUMA
hint (srcLocHint=HostNumaCurrent) that is a no-op on WSL2 single-NUMA
hosts but allows the driver to pick the correct GPU<->CPU path on
multi-socket Linux boxes.

The other 142 cudaMemcpyAsync call sites in src/ remain unchanged —
they are mostly D2D copies inside the inference loop or one-shot
startup paths where the attribute surface has no leverage.

verify-fast green, no regression vs. tests/perf_baseline.json.
