## Method

| Item | Setting |
|---|---|
| Server per arm | fresh container per (model, engine, trial), engine order alternates per trial (imp first in trials 1 and 3) |
| imp flags | `imp-server --max-concurrent 16 --set runtime.max_batch_size=16 --set speculative.mtp_k=0 --set speculative.ngram=false` |
| vLLM flags | `--max-model-len 16384 --max-num-seqs 16`, `VLLM_WSL2_ENABLE_PIN_MEMORY=1`, `--ipc=host`, defaults otherwise (no speculation) |
| tg128 | 1 stream, 128 tokens, `ignore_eos`, 1000 / TPOT p50 (`serving_kpi.py`, 5 requests) |
| ttft_short | TTFT p50 of the tg128 requests (~22-token prompt, streamed) |
| ppN | prompt tokens / mean latency of `max_tokens=1` requests (`serving_kpi.py --prompt-tokens N`, 8 requests, 4 above 4096); unique prompt heads, so no prefix-cache hits; includes HTTP and tokenization |
| c4, c16 | `conc_client.py` aggregate tok/s, 300-token greedy answers, `ignore_eos`, ~40-token prompts, median of 3 waves (BENCHMARKS.md method) |
| c16L | as c16 with ~1000-token prompts (`PLEN=1000`) |
| VRAM | `nvidia-smi memory.used` peak minus pre-start baseline, 500 ms samples; vLLM preallocates `gpu_memory_utilization` 0.92 |
| Host guard | `gpu-busy-check.sh` + 1-min load <= nproc/4 before every arm; SM clock p50 at >= 50 % util 2752-2925 MHz on every completed arm |
| Spread | value = median of 3 starts; per-cell min-max in `vllm_gap_table.py` output |

- vLLM's window holds 29 of 30 layers' per-layer kernels (29 calls/step); per-call times below are window-independent.
- MoE expert GEMM per layer: imp gate 38.8 + up 37.8 + down 51.7 = 128.3 us (3 launches, grid 170, 288 threads); vLLM fused gate_up 66.1 + down 37.7 = 103.8 us (2 launches, FlashInfer CUTLASS, grid 170, 384 threads).
- vLLM fuses residual add + RMSNorm + FP4 quantize into one Triton kernel per site (`triton_red_fused_add_mul_rms_norm_scaled_fp4_quant`, 29/step); imp runs ~571 norm/quant/elementwise launches per step.
- imp kernel sum exceeds its union by 824 us (PDL overlap): class deltas are upper bounds on step savings.
